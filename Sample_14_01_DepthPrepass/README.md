# Sample_14_01: Z Prepassの深度を本描画へ引き継ぐ版

元の `Sample_14_01` をコピーした比較用プロジェクトです。元サンプルのソースと共有 `MiniEngine` のソースは変更していません。現在の作業内容を含めてソース・Assetsをコピーし、Visual Studioのキャッシュと既存のビルド出力は除外しました。

## 起動と比較

`Run.cmd` で起動します。Releaseの実行ファイルがあればReleaseを、なければDebugを使います。Assetsのある作業フォルダーも設定します。

Visual Studioでは `Sample_14_01_DepthPrepass.sln` を開き、x64でビルド・実行してください。VS2022 / v143を使用します。実行ファイルは `bin/x64/Debug` または `bin/x64/Release` に出力されます。

- 起動時は深度共有がONです。
- **F1**で共有ONとBaseline（元の深度管理方式）を切り替えます。
- タイトルバーにモードとGバッファ／フォワード描画のPS実行回数を表示します。
- カメラ操作は元のサンプルと同じです。

## 変更した描画処理

`RenderingEngine.cpp` の `RenderToGBuffer()` と `ForwardRendering()` で、Z PrepassのDSVをそのまま本描画に指定します。

```text
Z Prepass: 専用の深度バッファと参照用深度テクスチャを生成
    ↓ 同じDSVを保持して引き継ぐ
Gバッファ描画: 色のRTだけをクリアし、事前深度でテスト
    ↓
フォワード描画: 同じ事前深度でテスト
```

本描画の直前に共有深度をクリアしません。既存のモデル用PSOは `LESS_EQUAL` ＋深度書き込み有効のままです。Z Prepassで記録された最前面と同じ深度は通り、奥のフラグメントは不合格になります。`EQUAL` 専用PSOや共有エンジンの変更は加えていません。

Gバッファ用PSの両エントリと `Assets/shader/sample.fx` のPSに `[earlydepthstencil]` を追加しています。隠れたフラグメントをピクセルシェーダーの実行前に判定するためです。

輪郭用の深度テクスチャは、深度テスト用のリソースとは別なので、これまでどおりシェーダーで読み取れます。シャドウ、ブルーム、DOFの処理内容も元のままです。

Baselineでは、Z Prepass自体を省略せず、元サンプルと同じ独立したGバッファ用深度を本描画に使用します。両モードで同じシェーダーと計測処理を使い、深度の引き継ぎによる差を比較します。

## 実行検証

NVIDIA Quadro P620でDebug/x64とRelease/x64をビルドし、各構成で3視点を比較しました。全ケースでメインRTのHDR画像（DDS）がバイト単位で完全一致しました。Debug構成のD3D12エラーは0件です。

本描画（Gバッファ＋フォワード）の1フレーム当たりのPS実行回数は次のとおりでした。DebugとReleaseで同じ値でした。

| 視点 | Baseline | 深度共有ON | 削減率 |
|---|---:|---:|---:|
| 初期視点 | 1,028,316 | 921,376 | 10.40% |
| 斜めから | 983,895 | 921,294 | 6.36% |
| 近距離 | 1,091,308 | 921,243 | 15.58% |

この数値はD3D12の `PIPELINE_STATISTICS.PSInvocations` です。GPUが報告するヘルパー実行を含む場合があります。**FPSやGPU時間の改善率ではありません。** Z Prepassの描画回数や頂点処理を削減したわけでもありません。

集計値と画像のSHA256は `ValidationResults.json` に保存しています。生成画像・個別レポート・D3D12メッセージは `Sample_14_01/validation/Debug` と `Release` にあります。このフォルダーはGitの対象外です。

再現する場合は、このフォルダーで次を実行します。

```bat
Run.cmd --validate --baseline
Run.cmd --validate
```

`--validate` は固定カメラで12フレーム実行し、PNG・浮動小数点DDS・JSON・診断ログを保存して終了します。`--view-side` または `--view-close` を追加すると検証視点を変更できます。キャプチャ、計測、またはDebug構成のD3D12エラー検査に失敗すると終了コード2を返します。

## 適用範囲

現在のサンプルの不透明モデルを対象にしています。事前描画と本描画でモデル、頂点変換、カメラ、ラスタライズ設定が一致することが前提です。アルファ抜き、半透明、スキニング、頂点変形を追加する場合は、Z Prepass側も同じ可視性・形状に対応させる必要があります。

主要な変更ファイルは `RenderingEngine.cpp/.h`、上記2つのシェーダー、`main.cpp` です。`DepthPassMetrics.h` と `DepthPrepassValidation.h` は比較・検証用に追加しています。
